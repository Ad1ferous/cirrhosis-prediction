# Отчёт о проделанной работе по дисциплине "Бизнес-применение МО"

В рамках задания была проведена подготовка ML-проекта (предсказание цирроза печени) к production-стандартам. 

## 1. Управление зависимостями и окружением (Poetry)
- Инициализирован менеджер пакетов Poetry.
- Созданы файлы `pyproject.toml` и `poetry.lock` для строгой фиксации версий всех библиотек (pandas, scikit-learn, imbalanced-learn, optuna и др.). Это гарантирует воспроизводимость результатов на любом компьютере.
- Виртуальное окружение изолировано от системного Python.

## 2. Интеграция виртуального окружения в Git
- Добавлен файл `.gitignore`, в который включена папка виртуального окружения (`.venv`, `venv`), а также временные файлы и кэш Jupyter. Это соответствует главному правилу MLOps: не хранить тяжелые бинарники окружения в системе контроля версий.
- Файлы зависимостей (`pyproject.toml`, `poetry.lock`) закоммичены, чтобы любой разработчик мог развернуть среду одной командой `poetry install`.

## 3. Автоматизация проверки кода (Pre-commit и линтеры)
- Настроен хук `pre-commit` с использованием форматтера `black` и линтера `flake8`.
- Теперь при каждой попытке сделать коммит код автоматически проверяется на синтаксические ошибки и приводится к единому стандарту PEP8.
- Все ошибки линтеров успешно устранены, проверки проходят со статусом Passed.

## 4. Рефакторинг кода под production-стандарты
- Исследовательский код, подбор гиперпараметров (Optuna, SMOTE, GridSearch) и анализ данных остались в Jupyter-ноутбуках в папке `notebooks/` (`trees.ipynb`), так как ноутбуки — это среда для экспериментов.
- Для production-уровня вынесен отдельный скрипт `train_model.py`. 
- В нем применены лучшие практики:
  - Использование `sklearn.pipeline.Pipeline` и `ImbPipeline`, что предотвращает утечку данных при предобработке и балансировке.
  - Жесткая фиксация `random_state=42` во всех моделях и разбиениях для полной воспроизводимости.
  - Удален "мертвый" код, закомментированные участки и лишние выводы.

## Как развернуть проект
1. Клонировать репозиторий.
2. Установить зависимости: `poetry install`.
3. Активировать окружение: `poetry shell`.
4. Запустить production-скрипт: `python train_model.py`.


### Описание проекта
Данный проект направлен на разработку модели машинного обучения для прогнозирования различных исходов у пациентов с циррозом печени. Модель будет классифицировать пациентов по нескольким категориям исходов заболевания и помогать врачам принимать более обоснованные клинические решения.

Наш проект поможет **выявлять риски летального исхода на ранней стадии** и **улучшать выживаемость пациентов** за счет своевременных медицинских вмешательств. *(мб что-то еще)*

### Цель проекта
Разработать точную модель мультиклассовой классификации исходов цирроза печени.

### Задачи проекта
1. Провести обработку данных и EDA.
2. Выполнить feature engineering *(если нужно будет)*
3. Обучить несколько моделей и сравнить результаты их обучения.
4. Представить отчет о проделанной работе.
